# Окрема сторінка повідомлень

## Поведінка

- Дзвіночок зберігає короткі анонси й лічильник непрочитаного. Відкриття списку не позначає повідомлення прочитаними.
- Натискання повідомлення веде на `/notifications/{announcement|task|genehelp}/{id}` у тій самій вкладці. Повний текст не обрізається, абзаци збережені, посилання на матеріали/завдання/GeneHelp винесені під текст.
- `/notifications` містить фільтри «Усі» / «Непрочитані», по 20 записів на сторінку, оновлення та групове позначення прочитаного. Повернення з повідомлення зберігає фільтр і сторінку списку.
- Прочитане підтверджується сервером; помилка збереження не блокує текст і має окрему кнопку повтору. Запізніла відповідь списку не повертає вже підтверджене повідомлення в непрочитані.
- Список і читання використовують один account-scoped provider із тим самим хвилинним оновленням, оновленням на фокус і відкриття дзвіночка. Паралельні оновлення об’єднані; при зміні акаунта стан скидається, старі відповіді ігноруються.
- Додано компактну контекстну інструкцію. Немає нових адміністративних інструкцій.

## Дані й обмеження

Нові міграції та Edge Functions не потрібні: використано наявні авторизовані RPC / RLS. Прямі посилання на оголошення читаються через published-only RPC, на завдання — через власні записи `task_notifications`. Маршрути вимагають входу, зберігають адресу повернення після авторизації, не запускають завантаження даних проєкту і мають noindex.

Поточний ліміт нагадувань і GeneHelp залишено без змін: останні 50 кожного типу в списку. Для прямого посилання GeneHelp використовується наявний RPC до 100 останніх повідомлень, без обходу заборони прямого доступу до його таблиці. Старіші записи GeneHelp потребували б окремого серверного API історії; тут воно не додається. В оголошеннях діє чинний API-ліміт PostgREST.

Матеріали й CTA допускають лише безпечні HTTP(S)-адреси. Текст рендериться як текст, не HTML. Запити GeneHelp відкриваються за локально сформованою канонічною адресою; зовнішні посилання — з `noopener noreferrer`.
