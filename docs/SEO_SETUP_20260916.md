# SEO для пошуку за тематичними запитами

## Що підготовлено

| Сторінка | Пошуковий намір |
| --- | --- |
| `/` | родове дерево онлайн, родовід українською, дослідження родоводу |
| `/rodove-derevo-onlain/` | як створити родове дерево, генеалогічне дерево, перенесення GEDCOM |
| `/poshuk-predkiv/` | як знайти своїх предків, пошук предків за прізвищем, історія сім’ї |
| `/arkhivni-dokumenty/` | архівні документи для родоводу, метричні книги, джерела генеалогії |
| `/posibnyk-z-henealohii/` | посібник із генеалогії, самостійне дослідження роду |

Це тематичні групи, а не оцінка частотності: даних Google Search Console про попит і позиції в цій роботі не отримано.

Головна має тематичні title, description, Open Graph і Twitter. Основний видимий слоган «Не губи сліди свого роду» та початковий підзаголовок залишаються на головному місці. Зміст у початковому HTML доступний без виконання JavaScript і замінюється React після запуску. Окремі публічні матеріали — повні HTML-сторінки без залежності від застосунку чи авторизації, з власними canonical, описами, JSON-LD та змістом. Головна, матеріали, FAQ, можливості й тарифи пов’язані звичайними HTML-посиланнями. Основний `sitemap.xml` є індексом і посилається на `sitemap-pages.xml`, `sitemap-guides.xml` та карту каталогу «Загуляки». Усі тринадцять публічних URL збережені в дочірніх картах; приватні маршрути туди не потрапляють.

Ключові фрази, пошуковий намір, редакційні теги, дати публікації та статус індексації зберігаються в `publicSeoRegistry` у `src/utils/publicSeoContent.ts`. Генератор перевіряє дублікати шляхів, дати, внутрішні посилання та включає до sitemap лише опубліковані індексовані записи. Список фраз не виводиться як застарілий `meta keywords`: він використовується для структури матеріалів, заголовків, внутрішніх посилань і JSON-LD.

Не додано meta keywords: Google їх не використовує для пошуку. Не заявлено рейтинги, відгуки, нагороди чи гарантовані позиції.

Прочитано текст PDF через Google Drive. Метадані доступу підтвердили `anyone: reader`. Сторінка посібника містить стислий адаптований виклад п’яти етапів, зазначення автора та посилання на повний PDF. Це не повне перевидання. Історичні приклади архівних шифрів і старі тарифні обмеження сторонніх сервісів не перенесено як перевірені актуальні дані. Вихідний PDF та його права доступу не змінювалися.

## Редагування

1. Змінювати основний текст у `src/utils/publicSeoContent.ts`.
2. Після змістовного оновлення змінити `modified` у `scripts/generate-public-seo.mjs`. Дата не повинна автоматично оновлюватися на кожній збірці.
3. Запустити `npm run generate:seo`. Команда оновлює HTML, sitemap та короткі посилання для React; тексти статей не додаються до основного JavaScript-пакета.
4. Запустити `npm run build`. Збірка перевіряє синхронність згенерованих файлів.

Нові матеріали використовують уже наявну згоду на аналітичні cookies. До дозволеного переліку додано лише чотири точні публічні маршрути; query, fragment та приватні маршрути не передаються.

## Перевірено локально

- Цільові перевірки: метадані, початковий HTML, sitemap index і дочірні карти, посилання на посібник, CSP/JSON-LD, каталог і приватність аналітики.
- `npm run build` успішний, перевірка публічних sourcemap успішна. Залишаються попередження про великі пакети JavaScript, змішані статичні/динамічні імпорти та незаповнені реквізити legal config.
- Повний `verifyHostingBuild` пройшов на копії production-збірки з порожнім тестовим каталогом. Робочу БД не читали й не змінювали; масову генерацію записів каталогу не запускали.
- У браузері: головна, навігація до посібника, усі чотири матеріали; помилок у консолі не виявлено. Перевірено вузький екран сторінки посібника: один H1, без горизонтального переповнення.
- `git diff --check` пройшов.

## Що потрібно після публікації

Зміни підготовлені локально; commit, push та production deployment у цій роботі не виконувалися.

1. Опублікувати через звичайний процес проєкту. І Vercel, і GitHub Pages використовують `npm run build`, який перевіряє SEO-файли. Не завантажувати локальний `dist` вручну: штатний процес додатково генерує каталог «Загуляки».
2. Перевірити HTTP 200 і метадані головної та чотирьох нових адрес на `https://trekerrodu.com.ua`. Перевірити `/robots.txt`, `/sitemap.xml` та `/sitemap-zagulyaky.xml`.
3. У Google Search Console вибрати підтверджену властивість сайту, надіслати або перевірити обидві карти сайту. Якщо властивість ще не підтверджена, потрібна дія власника облікового запису/домену; коди підтвердження не вигадувати.
4. Через перевірку URL запросити повторну індексацію головної та чотирьох нових сторінок.
5. Порівнювати небрандові запити: покази, переходи, CTR, середню позицію й сторінки входу. Після накопичення даних уточнювати теми за фактичними запитами.

Переобхід може тривати від кількох днів до кількох тижнів. Технічна доступність і новий текст не гарантують індексацію або певну позицію.
