# Розширена глобальна аналітика адміністратора

## Що додано

- Онлайн: унікальні псевдонімізовані користувачі з сигналом активного часу за останні 120 секунд. Кілька вкладок одного користувача не збільшують лічильник.
- Графіки за 7 / 30 / 90 днів: користувачі, сесії з активністю, перегляди розділів та сумарний активний час. Точні числа й середній час доступні в таблиці під графіками.
- Середній активний час на сесію та користувача за період, активність за годинами й розподіл сесій за пристроями.
- Повний каталог розділів із пошуком: зокрема Місця, контекст особи, Нотатки, Сузір’я роду, віялова/кругова діаграми, прямі предки, переглядач документів і приватні «Мої матеріали» Загуляк.
- Виправлено розбіжність білого списку: фронтенд надсилав `notes`, але Edge Function та SQL раніше відхиляли такі пакети.
- Старі звіти дій, воронки й утримання та експорт CSV збережені. Помилка одного звіту не приховує всі інші.

## Значення показників і приватність

Це **глобальна внутрішня аналітика**, без фільтра конкретного проєкту. Не є лічильником усіх відвідувачів публічного сайту: потрібні авторизація і чинна згода на аналітику. Адміністративні сесії, публічний каталог Загуляк, публічні сторінки й чутливі спільні графи не відстежуються. Відмова від аналітики не змінюється.

Час рахується лише у видимій вкладці з фокусом, не довше 5 хвилин без взаємодії. Сесія — робота у вкладці, а не окремий вхід в обліковий запис чи автоматичний 30-хвилинний «візит». Сесія, відкрита до початку періоду, враховується, якщо була активність у періоді. Час підсумовується за часом подій, не з довічних лічильників сесії; точність на межах періоду обмежена хвилинним надсиланням накопиченого часу.

Онлайн — наближений індикатор: сигнали надходять приблизно щохвилини, тому нова активність з’являється із затримкою, а після закриття вкладки користувач може залишатися в лічильнику до 2 хвилин. Береться `occurred_at`, а не час повторного отримання пакета. Прострочені повторні надсилання та майбутні часові мітки не створюють хибний онлайн. Панель опитує лише легкий RPC раз на 30 секунд, тільки у видимій вкладці; одночасних запитів немає, завислий запит переривається через 15 секунд. Графіки оновлюються при виборі періоду/натисканні «Оновити звіти», не при кожному опитуванні онлайн.

Поріг приватності збережено: 1–4 користувачі → «< 5» і приховані метрики; 0 → справжній нуль. Приховані точки не перетворюються на нулі та не з’єднуються лінією. Поріг застосовується окремо до дня, години, пристрою і розділу. Унікальні користувачі за днями/годинами/пристроями не підсумовуються як унікальні за весь період.

Календар і години — `Europe/Kyiv`, включно з переходами літнього часу. Перший і останній день ковзного періоду можуть бути неповними. Сирові події зберігаються 90 днів, тому порівняння вибраних 90 днів із попередніми 90 днями вимкнено. Нові коди розділів не можуть відновити історичні дані, що раніше не збиралися чи відхилялись.

Сервер перевіряє `analytics.view`; таблиці подій/сесій залишаються закритими для браузера. Імена, URL, пошукові запити, ID осіб/проєктів, вміст документів та ключі акторів у звітах не повертаються. Нових Realtime-каналів, ідентифікаторів або додаткових персональних полів немає.

## Впровадження: спочатку тестове середовище

Зміни підготовлено локально. Робочу базу, Edge Functions і хостинг під час цієї задачі не оновлювали.

Потрібні **всі три частини**, у такому порядку:

1. Застосувати `supabase/migrations/202609070003_admin_analytics_traffic.sql` через звичайний процес міграцій до вибраного тестового Supabase. Міграція потребує попередньої основи аналітики/RBAC. Вона не видаляє дані й не скидає згоду; додає частковий індекс активності, оновлює білий список і звіти.
2. Оновити Edge Function **`collect-product-analytics`** з новим `payload.ts`, зберігши JWT-перевірку, існуючі секрети й дозволені origins. Лише оновлення фронтенду недостатньо: старий колектор відхилить нові коди.
3. Розгорнути новий фронтенд у тестовому середовищі. Після перевірки повторити погоджений процес для робочого середовища.

Для великої таблиці подій запланувати створення індексу в малонавантажений час: звичайний `CREATE INDEX` у транзакційній міграції тимчасово блокує записи. Новий індекс охоплює лише події активного часу. Тестувати план на реальному обсязі в staging, а не збільшувати `statement_timeout` наосліп.

Перевірка після тестового деплою:

- Неадміністратор із дозволеною аналітикою відкриває Місця, Нотатки, Сузір’я; через 1–2 хвилини події прийняті колектором без помилок. Для 1–4 користувачів очікується «< 5», а не точне число.
- Користувач без згоди не надсилає подій. Інша роль адміністратора без `analytics.view` не може викликати звіти; звичайний користувач не може читати таблиці аналітики.
- Адміністратор відкриває Аналітику, змінює період, метрику, тему, шукає розділ і перевіряє таблицю. Кнопка «Оновити звіти» оновлює кінець періоду.
- Перевірити лічильник після відкриття другої вкладки, закриття/приховування користувацької вкладки та після втрати мережі.

## Локальні перевірки

```powershell
npm.cmd run typecheck
node --test test/adminAnalyticsTraffic.test.ts test/integration/adminAnalyticsTrafficDatabase.test.ts
npm.cmd test
npm.cmd run build
```

Інтеграційний тест виконує справжні DDL, функцію приймання, RLS, перевірку ролей і нову міграцію в ізольованому PGlite. Синтетичний замір: 80 000 подій / 1 000 користувачів — приблизно 338 мс на 90-денний звіт і 2 мс на онлайн у локальному запуску. Це не замір продуктивності робочого Supabase і не гарантія для будь-якого обсягу даних.

Браузерна перевірка використовує справжню AdminPanelPage з підставними відповідями сервісів, без підключення до робочої бази. Інструкції й тимчасові файли стенда — `.tmp/admin-analytics-qa/`.

Перевірено світлу й темну тему, екран 390 px, 90-денний графік/таблицю, пошук розділу, нульову активність, приховані вибірки та відсутню міграцію. Усунено горизонтальне розширення блоків на мобільному екрані. Консоль браузера — без помилок/попереджень.

Повний локальний набір: 2341 тест, 2336 пройдено, 5 пропущено, 0 помилок. Збірка успішна; наявне попередження Vite про великі chunks зберігається.
