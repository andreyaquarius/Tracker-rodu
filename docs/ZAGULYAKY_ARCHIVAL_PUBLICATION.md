# Підтвердження архівних записів і фото

## Що змінено

- У черзі модерації для історичних матеріалів можна підтвердити «опубліковане архівне джерело, без даних живих осіб» і обрати джерело. Якщо придатне джерело одне, воно вибирається автоматично.
- Підстава `historical_archive` та публікація записуються однією транзакцією через `admin_publish_archival_zagulyaka_v1`. Дата згоди не вигадується, `possible_living_person` масово не скидається.
- Потрібні повноваження модератора, актуальна версія запису та прив’язане джерело з описом/архівом/URL без позначки `restricted`. Заблоковані записи цією дією не розблоковуються.
- Рішення прив’язане до наявного відбитка вмісту запису та джерел. Зміни в них потребують повторної перевірки. Документована згода для справді живих осіб залишається окремою підставою.
- Кнопка біля непублічного фото в черзі спершу підтверджує запис, потім створює копію лише вибраного вкладення. Основна кнопка публікації обробляє всі ще не опубліковані вкладення послідовно.
- Якщо збій стався лише з одним файлом, запис залишається опублікованим і відкритим для повторної спроби. Реальні помилки не приховуються. Поточний протокол вкладень v2 повторно використовує вже підготовлену копію.

## Застосування

1. Застосувати forward-міграцію `202609120001_zagulyaky_archival_publication.sql` звичайним процесом деплою міграцій.
2. Розгорнути фронтенд із цими змінами. Окремих змін Edge Function вкладень у цьому виправленні немає.
3. Перевірити один архівний запис із фото: обрати архівну підставу, підтвердити, відкрити опублікований запис і вкладення.

Міграція не підтверджує наявні записи автоматично і не видаляє даних. Старі записи в журналах також не видаляються.

## Локальна перевірка

`test/integration/zagulyakyArchivalPublicationDatabase.test.ts` виконує справжні SQL-функції у PGlite: модерація без згоди, права доступу, відкат помилкової перевірки, застаріле рішення, відкликання, чинна згода, порядок публікації фото й ідемпотентний повтор.

`test/zagulyakyPublication.test.ts` перевіряє послідовність клієнтських викликів, недоступні стани та частковий успіх. Браузерна перевірка використовує ізольовані тестові дані; вона не замінює перевірку після застосування міграції на сервері.
