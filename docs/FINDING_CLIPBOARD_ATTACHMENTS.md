# Скриншот у знахідку з буфера обміну

У формі створення та редагування знахідки можна вставити зображення через
Ctrl+V (⌘V на Mac) або кнопку **Вставити скриншот** у блоці «Файл знахідки».
На Windows область екрана можна скопіювати за допомогою Win+Shift+S, потім
повернутися до форми, натиснути в її полі та вставити скриншот.

Зображення отримує ім’я `screenshot-<дата>-<номер>.<формат>` і завантажується
через той самий `saveScan`, що й звичайний файл. Зберігаються папка проєкту,
політика вкладень, прогрес, перевірка тарифу й архівних реквізитів.
Чинний ліміт знахідки не змінено: один файл, до 25 МБ.
Після завершення завантаження потрібно зберегти знахідку.

Звичайний текст вставляється у поле без перехоплення. HTML та URL не
перетворюються на вкладення. Подія paste обробляється лише у відповідній
формі й діалозі; сусідні знахідки, вкладені вікна та інші модулі не отримують
скриншот. Буфер не читається у фоні. Якщо браузер не підтримує кнопку або
відмовив у доступі до буфера, інтерфейс пропонує Ctrl+V.

На час читання буфера та завантаження заблоковано повторне додавання,
збереження й закриття форми знахідки. Після помилки можна повторити вставлення;
неуспішний файл не записується у список вкладень.

## Перевірка

- `node --test test/clipboardImages.test.ts test/entitySaveWorkflow.test.ts`
- `npm test`
- `npm run build`
- Браузерна перевірка реального `ScanAttachmentsEditor` із локальним
  імітатором Drive: Ctrl+V, кнопка, текст, дві форми, вкладений діалог,
  ліміт файлів, обов’язкові реквізити, від’єднане сховище, помилка та повтор.

Міграція БД не потрібна: використовується наявний масив `scans`.
Робочий Google Drive під час локальної перевірки не змінювався.
